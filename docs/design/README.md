# 設計書一式の置き場

このフォルダに、**あなたが作る設計書**を置きます。いまは空です。

仕様書（`docs/spec.md`）とモックアップ（`mockup/`）を読んで設計に落としたものが、ここに揃っていきます。実装が終わったあとも、**実物と食い違ったままにしない**でください。この一式が提出物の中心です。

---

## 置くファイル

種類ごとに1ファイルです。ファイル名はこのとおりにしてください（教材の確認表と突き合わせるため）。

### 仕様を読む

| ファイル | 中身 |
|:--|:--|
| `feature-list.md` | 機能一覧（F-xx）と、今回作らないもの |
| `questions.md` | 確認事項リスト（Q-xx）と、返ってきた回答 |

### 画面

| ファイル | 中身 |
|:--|:--|
| `screen-list.md` | 画面一覧（SC-xx） |
| `screen-flow.md` | 画面遷移図 |
| `screen-items.md` | 画面項目定義（主要な画面のみ） |
| `input-check.md` | 入力チェックとエラーメッセージの一覧 |

### データ

| ファイル | 中身 |
|:--|:--|
| `concept.md` | 概念データ設計（エンティティと関連・ER図） |
| `table.md` | テーブル定義書 |
| `crud.md` | CRUD表 |

### 裏側

| ファイル | 中身 |
|:--|:--|
| `permission-matrix.md` | 権限マトリクス |
| `api.md` | ルーティング一覧と、公開APIの設計 |
| `state-table.md` | 状態遷移図 |
| `sequence.md` | 代表的な処理のシーケンス図 |
| `exceptions.md` | 例外方針 |

### 締め

| ファイル | 中身 |
|:--|:--|
| `acceptance.md` | 機能ごとの受け入れ条件 |
| `test-viewpoints.md` | テスト観点 |

---

## 決まりごと

- **図はMarkdownの中にMermaidで書きます**（画像ファイルを置かない）。ER図・画面遷移図・状態遷移図・シーケンス図はすべてMermaidです
- **1ファイルに複数の種類を詰め込まない**。「どこに何が書いてあるか」が探せなくなります
- 実装中に決めが変わったら、**コードではなくここを先に直します**
- 発展課題に挑むときも、**設計をここに足してから**Issueにします
